## 1. Project Overview: Task Manager API
We are building a RESTful Task Manager CRUD API using **Node.js** and **Express.js**. This API serves as the backend for a To-Do/Task Manager application, allowing users to create, view, update, and delete tasks.

### Data Model (`Task`)
A **Task** represents a single to-do item in our system. Every task created, stored, or returned by our API must follow this exact structure (blueprint):

* `id`: Unique identifier *(Auto-generated by the server)*
* `title`: String *(Required — The main name of the task)*
* `description`: String *(Optional — Extra details or notes about the task)*
* `status`: String (`pending` | `completed`) *(Defaults to `pending` when a task is created)*

#### Example `Task` Object (JSON)
*(Use this format when testing `POST` and `PUT` requests in Postman)*
```json
{
  "id": "1",
  "title": "Build Express CRUD endpoints",
  "description": "Complete GET, POST, PUT, and DELETE routes for tasks",
  "status": "pending"
}
```

### Target API Endpoints
* `GET /tasks` — Fetch all tasks
* `GET /tasks/:id` — Fetch a single task by ID
* `POST /tasks` — Create a new task
* `PUT /tasks/:id` — Update an existing task by ID
* `DELETE /tasks/:id` — Delete a task by ID

## 3. Git Branch & Commit Naming Guide
To keep our repository organized across all 19 members, please prefix your branch names and commit messages with the label that matches your work:

* `feat/` — Adding new API routes or code *(e.g., `feat/create-task-endpoint`)*
* `fix/` — Fixing a bug in existing code *(e.g., `fix/task-status-validation`)*
* `test/` — Adding Postman collections or test logs *(e.g., `test/log-delete-status-codes`)*
* `docs/` — Updating `README.md`, slides, architecture, or demo notes *(e.g., `docs/add-demo-script`)*
* `chore/` — Project setup or folder organization *(e.g., `chore/init-express-server`)*
