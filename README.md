## 1. Project Overview & Quick Start

We are building a RESTful Task Manager CRUD API using **Node.js** and **Express.js**. This API allows users to create, view, update, and delete tasks in memory without a database.

### Run Locally
```bash
git clone https://github.com/dakilla-ctrl/BT-BD-Nov26-Grp5.git
cd BT-BD-Nov26-Grp5
npm install
npm start   # Server runs on http://localhost:3000
```

## 2. API Contract (Build & Test Against This Immediately)

All sub-teams can work **in parallel** using this agreed blueprint—testers and doc writers do not need to wait for the routes to finish before setting up their work.

### Task Data Model
Every task created, stored, or returned by our API must follow this exact structure:

* `id`: String — Unique identifier *(auto-generated by the server)*
* `title`: String — **Required** *(the main name of the task)*
* `description`: String — Optional *(extra details or notes about the task)*
* `status`: String (`"pending"` | `"completed"`) *(defaults to `"pending"` when a task is created)*

### Example `Task` Object (JSON)
*(Use this exact format when testing `POST` and `PUT` requests in Postman)*
```json
{
  "id": "1",
  "title": "Build Express CRUD endpoints",
  "description": "Complete GET, POST, PUT, and DELETE routes for tasks",
  "status": "pending"
}
```

### Target API Endpoints
* `GET /tasks` — Fetch all tasks (`200 OK`)
* `GET /tasks/:id` — Fetch a single task by ID (`200 OK` / `404 Not Found`)
* `POST /tasks` — Create a new task (`201 Created` / `400 Bad Request`)
* `PUT /tasks/:id` — Update an existing task by ID (`200 OK` / `404 Not Found`)
* `DELETE /tasks/:id` — Delete a task by ID (`200 OK` / `404 Not Found`)

## 4. Git Branch & Commit Naming Guide

> **Important:** Never commit `node_modules/` or `.env` files to the repository.

To keep our repository organized across all 19 members, prefix your branch names and commit messages with the label that matches your work:

* `feat/` — Adding new API routes or code *(e.g., `feat/create-task-endpoint`)*
* `fix/` — Fixing a bug in existing code *(e.g., `fix/task-status-validation`)*
* `test/` — Adding Postman collections or test logs *(e.g., `test/log-delete-status-codes`)*
* `docs/` — Updating `README.md`, slides, architecture, or demo notes *(e.g., `docs/add-demo-script`)*
* `chore/` — Project setup or folder organization *(e.g., `chore/init-express-server`)*
